This walkthrough deploys [`samples/hello-aspire`](https://github.com/lv3rmeulen/Deployify/tree/main/samples/hello-aspire)
to Docker Compose. It needs nothing but Docker, so it's the quickest way to see the whole
plan → publish → apply → destroy loop. The code on this page is read from the sample itself,
which CI builds and deploys every night.

## The app

The sample has one of each kind of resource Deployify deploys:

- `api`, a **project**: an API that counts visits in Redis and logs them in Postgres
- `web`, a **Dockerfile** build: a static site served by nginx
- `cache` and `postgres`, **containers**: Redis, and Postgres with the `visitsdb` database
- `admin-key`, a **secret parameter**: the key the API's `POST /reset` asks for

## Deploy it

You need the .NET 10 SDK, Docker (or Podman) and [the `deployify` tool](/Deployify/getting-started/installation/).

<Steps>

1. Clone the repository and go to the AppHost:

   ```bash
   git clone https://github.com/lv3rmeulen/Deployify.git
   cd Deployify/samples/hello-aspire/HelloAspire.AppHost
   ```

2. Choose the admin key. `admin-key` has no default, so you supply it, here with Aspire's
   `Parameters__<name>` variable (a `-` in the name becomes `_`):

   ```bash
   export Parameters__admin_key=change-me
   # PowerShell: $env:Parameters__admin_key = "change-me"
   ```

   Deployify keeps secret values out of `compose.yml`: the key goes into the api's `.env` file.

3. Preview the deployment. Deployify runs the AppHost to get Aspire's manifest, writes the
   Compose files to `deployify-output/` and compares them with what's running:

   ```bash
   deployify plan
   ```

   Expect `4 to create`: `cache`, `postgres`, `api` and `web`. The Redis and Postgres passwords
   Aspire asks for are generated once and saved in `deployify-parameters.json`, so every later
   deploy reuses them.

4. Build the images into your local Docker: `api` with `dotnet publish`, `web` with `docker build`:

   ```bash
   deployify publish
   ```

5. Deploy. `cache` and `postgres` go before `api` because `api` depends on them, and each wave
   has to be healthy before the next one starts:

   ```bash
   deployify apply --auto-approve
   ```

6. Call the API and open the site:

   ```bash
   curl http://localhost:8080/
   # {"message":"Hello from Aspire, deployed by Deployify","visits":1,"logged":1}

   curl http://localhost:8085/

   curl -X POST -H "X-Admin-Key: change-me" http://localhost:8080/reset
   # 204 No Content; without the key, 401
   ```

7. Look around, then clean up:

   ```bash
   deployify status                         # the rollout you just ran
   deployify destroy --auto-approve --volumes
   ```

</Steps>
